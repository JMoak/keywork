> must land behind an engine port with its own scoping overlay first. This is that overlay. It

> as of 2026-09-03; where it speaks it wins over `60` and D5's capstone sentence. Once Jordan
> picks an option the tasks become buildable and this file gains a ledger.
>
> **Standing guardrails (unchanged):** OpenCode is MIT and its LSP layer may be adapted with
> attribution in `NOTICE`; this overlay only cites it and every task below is `OWN`. Crush is
> never a source. The user commits; agents never `git commit` or `git push`.

## Where the tree stands

W10 (113) landed the non-LSP intelligence: the repo map (`engine/src/repomap/{extract,scan,map}.ts`,
heuristic regex extractors for ts / js / py / go / rs / md, cross-file reference ranking, an
incremental cache) injected through `SystemPromptOptions.repoMap` under a budget of
`min(2048, window / 32)` tokens, refreshed after tool writes. Two seams already exist that LSP
would ride:

- `editTool(scope, onSaved?)` and `writeTool(scope, onSaved?)` (`engine/src/tools/edit.ts:14`,
  `write.ts:12`) call `onSaved(target)` after a successful write; `cli/src/compose.ts`
  `refreshingOnSave` wraps it to mark the repo map stale. The callback is fire-and-forget and
  returns nothing, which is the one thing LSP needs changed (see the port).
- `ContextInjection` (`engine/src/session/journal.ts:24`) with `InjectionSource` values such as
  `"repo-map"` carries the A19 rule: every context injection is a journal event and a session
  entry, so replay reconstructs what the model saw.

Process hygiene for child servers exists too: `engine/src/proc.ts` `killTree` / `within`, and
the MCP host's stdio fixture server (`engine/src/testing/mcp-fixture-server.ts`, profiles
`basic` / `silent` / `crash-once` / `leaky`) is the exact shape a fake language server takes.
Bus events are typed in `engine/src/bus.ts`; `tool.finished` carries the output string the
model sees. E8 sandbox modes (103) have not landed; nothing here may assume them.

## Why and why not

The repo map tells the model what exists. A language server tells it what it just broke.

Moments where LSP beats everything keywork has:

1. **The edit that does not type-check.** Today the model finds out on the next `bun run
   check` it chooses to run, often several tool calls later; with diagnostics in the edit's own
   result it finds out in the same turn, before it moves on. This is the one moment worth
   the machinery.
2. **Definition across files.** The regex map ranks files; it cannot say which `open` a call
   resolves to. `definition` and `references` answer that in one call instead of three greps.
3. **Rename safety.** A `rename` request is the only way to change a symbol everywhere without
   a regex guess. It is also the rarest need and the heaviest request.

Moments where it is pure cost:

- Prose, config, docs, and markdown work: no server, no value, and any spawn is waste.
- Short sessions on small repos: a TypeScript server needs 2 to 10 s to load a project; the
  CLI typecheck would have finished.
- Any language without a server on PATH: keywork must behave exactly as today.
- Compaction and memory: diagnostics are a snapshot of a file state that no longer exists a
  turn later; they must never be distilled or recalled.

**Tier.** The M2 public demo is the tiling-pane harness reaching "zero to working in 60
seconds"; nothing in that minute needs a language server, and a spawn during onboarding would
only add latency the screencast cannot afford. LSP is M3 depth (D5's capstone), landed after
the demo, and only its first rung before a second is earned.

**Recommendation: A, shipped alone, default `off`.** The same-turn type error is the whole
argument for LSP inside a coding agent, and it needs no new tool the model has to learn, no
permission rows, and no navigation grammar; it changes one string the model already reads. It
also exercises the entire hard part (detect, spawn, initialize, sync, wait, degrade, shut down)
against a real server, so if B is ever earned it is a two-point addition over a lifecycle that
already survived dogfooding. C is refused for v1 on the simplicity budget: its extra surface
is the part OpenCode's own docs steer users away from, and rename is the one request whose
failure mode (files half changed) is worse than not having it. Default `off` at landing is
honest about cost; flipping to `auto` is a decision after soak, not before (Q-L1).

## The engine port

One module, `engine/src/lsp/`, behind an interface the TUI never sees. The name says what it
gives, not how: `LanguagePort`. Option A uses `afterSave` only; B adds the four read methods.

```ts
export interface LanguagePort {
  afterSave(path: string, signal?: AbortSignal): Promise<readonly Diagnostic[]>;
  hover(at: Position): Promise<string | undefined>;
  definition(at: Position): Promise<readonly Location[]>;
  references(at: Position): Promise<readonly Location[]>;
  documentSymbols(path: string): Promise<readonly SymbolOutline[]>;
  facts(): LanguageFacts;
  dispose(): Promise<void>;
}

export interface Diagnostic {
  path: string;
  line: number;
  column: number;
  severity: "error" | "warning";
  message: string;
  source?: string;
}

export interface LanguageFacts {
  servers: readonly { language: string; command: string; state: ServerState }[];
}

export type ServerState = "idle" | "starting" | "ready" | "missing" | "failed" | "stopped";

export interface LanguageServerSpec {
  command: readonly string[];
  extensions: readonly string[];
  initialization?: Readonly<Record<string, unknown>>;
}

export function languagePort(scope: ToolScope, options: LanguagePortOptions): LanguagePort;

export interface LanguagePortOptions {
  servers: Readonly<Record<string, LanguageServerSpec>>;
  budgets?: { initializeMs: number; diagnosticsMs: number; idleMs: number };
  diagnostics?: DiagnosticsLog;
  spawn?: SpawnLike;
  now?: () => number;
}
```

**Lifecycle**, in the order a session experiences it:

1. **Detect.** `afterSave(path)` maps the extension through the server table; no entry means an
   empty result and no process. Detection is per language, not per file: one server per
   language per session, rooted at the tool scope's cwd.
2. **Spawn.** The command is resolved on `PATH` only. Not found is `missing`: the result is
   empty, a single `context.injected`-style notice is posted once per session per language,
   and the state never re-probes until the next session.
3. **Initialize.** `initialize` with the workspace root and a minimal client capability set
   (text sync full, publish diagnostics, and for B hover / definition / references /
   documentSymbol); `initialized`; a budget of 10 s (`budgets.initializeMs`). A server that
   misses the budget is `failed` for the session, with the reason in the engine
   `DiagnosticsLog`, never in the tool result.
4. **Sync.** The port keeps the set of documents it has opened. First touch sends `didOpen`
   with the file's current text; later touches send a full-text `didChange` (incremental sync
   is not worth its state). The agent's own write is the only change source keywork knows
   about; external edits are seen as a new `didOpen` on the next touch, the same rule the repo
   map uses.
5. **Wait.** After sync the port waits for `publishDiagnostics` for that URI with a budget of
   3 s (`budgets.diagnosticsMs`). Silence within budget returns what is held, which after a
   clean edit is nothing. The wait is bounded so a slow server can never stall the tool loop
   past the budget; the model gets the edit confirmation regardless.
6. **Idle shutdown.** A server with no touch for `budgets.idleMs` (default 10 min) receives
   `shutdown` then `exit`, then `killTree` if still alive, and returns to `idle`. Engine exit
   disposes every server the same way; the MCP host's release-by-construction rule applies.
7. **Crash containment.** An exit before `shutdown` marks the server `failed`, writes the
   exit code and the last stderr lines to the `DiagnosticsLog`, and never retries inside the
   session: a server that died once mid-edit has told you what it thinks of the project. The
   TUI crash log is not involved; this is an engine event, surfaced only through `/doctor`.

**The seam.** `onSaved: (path) => void` becomes `afterSave: (path, signal) => Promise<string |
undefined>` on `CoreToolOptions`: an observer that may return an annotation to append to the
tool result. The repo map adopter returns `undefined` and keeps its stale-marking. The edit and
write tools await it inside their own budget and append whatever comes back, so the tools know
nothing about language servers and `compose.ts` composes the two observers the way it already
composes `refreshingOnSave`. If the observer throws, the tool result is unchanged and the
throw goes to the `DiagnosticsLog`; a diagnostics failure can never fail an edit that
succeeded.

**How diagnostics enter the neutral format.** As text inside the `ToolResultPart.output` of
the edit or write that produced them, in a fixed block:

```
Replaced 1 occurrence in src/cache.ts

diagnostics (typescript) · 2 errors
src/cache.ts:14:7 · Type 'string' is not assignable to type 'number'.
src/cache.ts:31:3 · Property 'flush' does not exist on type 'Cache'.
```

Not a new `Part` type, and not a system-role message. `messages.ts` has six parts and every
provider mapping (`chat-wire.ts`, `responses-wire.ts`, `messages-wire.ts`, Bedrock) would grow a
case for a seventh that every wire format would only ever render as text anyway. A system-role
injection would cost tokens on every subsequent turn for a fact that is stale after the next
edit, and would need A19 journal entries to be replayable; the tool result is already the
session entry, already replays, already streams through `tool.finished`, and is exactly where
OpenCode put it. Severity: errors in full, warnings as a count on the header line (Q-L4), and
only the touched file's diagnostics (cross-file fallout waits for B's `workspace/diagnostic`
question, which is C territory today). The bus gains one event, `diagnostics.published:
{ path, count }`, so a future pane can stamp the moment; nothing subscribes to it in A.

**Config.** One key, user layer only, described per D9:

```ts
lsp: z.union([
  z.enum(["off", "auto"]),
  z.record(z.string(), languageServerSpec),
]).describe(
  "Language-server switch (114/F4): off spawns nothing; auto spawns the built-in server for a language the first time a tool edits one of its files, if the server's command is on PATH, and appends that file's diagnostics to the edit result; a table replaces or extends the built-ins per language ({ command, extensions, initialization }). Exists because a language server is a user-installed process with real memory and startup cost, so the decision to run one belongs to the user, and because the built-in table cannot know every project's server.",
),
```

Built-in table, mirroring the repo map's languages: `typescript` (`typescript-language-server
--stdio`, `.ts .tsx .mts .cts .js .jsx .mjs .cjs`), `python` (`pyright-langserver --stdio`),
`go` (`gopls`), `rust` (`rust-analyzer`). Four entries, no `env` (secrets never travel in
server arguments or environment; a server that needs credentials is out of scope), no
auto-download of anything, ever.

## Process and trust posture

- **User-installed binaries, PATH only.** keywork never downloads, never resolves through a
  package manager, never runs a `node_modules/.bin` path it did not get from PATH. Missing is a
  normal state with one calm notice: `no typescript language server on PATH · diagnostics
  off for .ts` posted once, in the page's notice grammar, never a modal.
- **Scope.** The server is rooted at the tool scope's cwd and receives only the paths the
  tools already confined through `confinedPath`; a linked dir (PD11) is a second workspace
  folder in `initialize`, never a second server.
- **Trust.** A server runs with the user's full authority the way `bash` does; it is executable
  code outside any jail (the 103 framing for MCP servers applies verbatim). Untrusted
  workspaces (the repo-map rule) spawn nothing: a hostile repo must not be able to pick the
  server via a project-layer table, which is why the key is user layer only.
- **Sandbox (E8, unlanded).** When E8 lands, the server spawns through the same runner seam as
  tools and inherits `workspace-write` confinement; until then it inherits nothing and the
  overlay says so. `read-only` mode may still run a server (it only reads), a decision for E8.
- **Headless parity.** `keywork run` and `chat` compose the same `afterSave`; the diagnostics
  block appears in `--json` tool output identically, and a `run` that exits disposes servers
  before `run.finished`.
- **Diagnostics log, not tool output, for failures.** Stderr, exit codes, and initialize
  timeouts go to the engine `DiagnosticsLog`, readable via `/doctor` `language servers` row
  (`typescript · ready · pid 4242` / `python · missing` / `rust · failed · exit 101`).

## Cost and endurance

| Dial | Budget | Why |
|---|---|---|
| Initialize | 10 s | tsserver on a mid-size repo loads in 2 to 8 s; beyond 10 s the server is not going to help this session |
| Diagnostics wait | 3 s per save | the tool loop must stay interactive; a slow publish returns empty and the next save catches it |
| Idle shutdown | 10 min | a session that stopped editing TypeScript should not hold 300 MB of tsserver |
| Memory | one server per language per session | never per file, never per pane; two panes on one workspace share the engine's port |
| Long sessions | settler-neutral | the after-turn settler (109) runs after the tool loop; diagnostics have already returned or timed out, and nothing in them enters compaction summaries or the memory flush (they are tool output, which compaction already treats as machine text) |
| Repo map interaction | none | both ride `afterSave`; the map marks stale and returns nothing, the port waits and returns text |

Startup is paid once per language, lazily, on the first edit of that language, never at
session start and never during onboarding. `keywork run` on a one-file fix pays it once and
disposes.

## Tasks

### F4a (2pt): `LanguagePort` lifecycle
`engine/src/lsp/`: the port, the JSON-RPC stdio client (hand-rolled framing over the existing
`proc.ts` helpers; `vscode-jsonrpc` is a pin the tree does not need for one method table),
detect / spawn / initialize / sync / wait / idle-shutdown / crash containment as above, the
built-in server table, `facts()`.
**Accept:** against `engine/testing/lsp-fixture-server.ts` (a stdio JSON-RPC fake with
profiles `basic`: publishes one error for any document containing `BROKEN` and none otherwise;
`slow-init`: answers `initialize` after the budget; `crash-once`: exits after `initialized`;
`silent`: never publishes) the port returns the diagnostic within budget, `slow-init` yields
`failed` with a log line and an empty result, `crash-once` yields `failed` and no retry inside
the session, `silent` returns empty at the budget, a missing command yields `missing` without a
spawn, idle shutdown sends `shutdown` then `exit` under a stepping clock and `killTree`s a
survivor, and `dispose()` leaves no live child (the MCP release-by-construction test shape).
**Strategy:** `OWN`.

### F4b (1pt): the after-save seam and the diagnostics block
`onSaved` becomes `afterSave` on `CoreToolOptions` (repo map adopter migrated); edit and write
append the returned annotation; `compose.ts` composes port and map; the `lsp` config key with
its built-ins; the once-per-language `missing` notice; the `/doctor` row; `diagnostics.published`
on the bus.
**Accept:** with `lsp: "off"` every request and tool result is byte-identical to today
(recording-provider fixture); with `auto` and the fixture server on PATH an edit introducing
`BROKEN` returns the confirmation line plus the block in the format above, a clean edit
returns the confirmation alone; an observer that throws leaves the result unchanged and logs;
headless `--json` carries the same block; the untrusted-workspace fixture spawns nothing; the
project-layer `lsp` key is refused with the standing user-layer-only message.
**Strategy:** `OWN`.

### F5 (2pt): read tools (option B, only if earned)
`hover`, `definition`, `references`, `symbols` as `defineTool` tools over the port, non-mutating,
registered beside the core four when the port is on; results rendered as `path:line:col ·
text` lists clipped to a budget.
**Accept:** round-trips on the fixture server's canned answers; unavailable language yields a
readable error result and no throw; tool coverage test updated; no permission rows added.
**Strategy:** `OWN`. After F4a + F4b and a dogfooding note in this ledger.

## Non-goals and what this overlay does not decide

- No auto-download, no package-manager resolution, no bundled servers.
- No per-file server fan-out, no pull diagnostics, no incremental sync, no `rename`, no
  `workspace/symbol` (all C, refused for v1).
- No TUI surface beyond the tool result and one `/doctor` row; no diagnostics pane, no gutter
  marks in the file pane (a future 94 question, not this overlay's).
- Diagnostics never enter memory, arcs, or compaction summaries.
- E8 sandbox binding for servers is E8's decision; this overlay only requires the spawn to go
  through whatever runner seam E8 lands.
- Whether the P2 server (80) exposes diagnostics to attached clients is P2's question.
